Design the ASSUREDIA AI ANALYSIS / REPORTS page as a top-level page in the Client Dashboard.

IMPORTANT:
This is a redesign of an existing Assuredia product.
Do NOT invent AI capabilities, backend functionality, APIs, database structures, or reports that do not already exist.
The current product uses Groq AI for failure analysis.
AI analysis is primarily associated with execution/package results, not individual tests unless explicitly available.

--------------------------------

AI ANALYSIS DETAILS

Clicking an analysis should open the detailed AI Analysis view.

Show:

Execution
Flow
Status
Risk Level

Then create these sections:

1. BUSINESS IMPACT

Explain the potential effect of the failure on the user/business.

2. ASSESSMENT

Show the AI-generated assessment of what happened.

3. RECOMMENDED ACTIONS

Show the recommended next steps generated by the AI.

4. FAILURE CONTEXT

Show the relevant execution information used for analysis.

5. SCREENSHOTS

Display screenshots when available.

6. ERROR / FAILURE INFORMATION

Show the relevant error message and failed execution context.

Do NOT expose internal prompts, API keys, model credentials, or sensitive system information.

--------------------------------

Example:

"AI Failure Analysis"

"Powered by Groq"

Use a small AI icon and subtle blue accent.

This is an analysis/reporting experience, not a conversational AI assistant.

The AI Analysis page should therefore act as the intelligence layer on top of execution data.

--------------------------------

IMPORTANT PRODUCT PRINCIPLE

Assuredia does NOT simply say:

"Test Failed."

It should help answer:

"What failed?"

"Why did it fail?"

"What is the potential business impact?"

"What should the team investigate next?"

The AI Analysis page should communicate that value clearly without pretending that the AI autonomously fixes the application.
